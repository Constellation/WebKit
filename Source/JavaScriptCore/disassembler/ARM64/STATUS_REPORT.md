## Architecture Summary

### Data Structures

```cpp
// Instruction entry (per encoding)
struct InstructionEntry {
    const char* name;         // "ADD_32_addsub_imm"
    const char* mnemonic;     // "ADD"
    uint32_t mask;            // Fixed bits mask
    uint32_t pattern;         // Fixed bits pattern
    uint16_t operandOffset;   // Index into operand table
    uint8_t operandCount;     // Number of operands
    uint8_t flags;            // Variant flags
};

// Operand descriptor
struct OperandDesc {
    uint8_t type;      // OP_REG_GPR_X, OP_IMM_UINT, etc.
    uint8_t subtype;   // Format variant
    uint8_t field1;    // Primary field index
    uint8_t field2;    // Secondary field index
};
```

### Operand Types Supported

**Registers (20 types):**
- GP registers: X (64-bit), W (32-bit), SP, XZR, WZR variants
- FP registers: B, H, S, D, Q (8/16/32/64/128-bit)
- SIMD: V registers
- SVE: Z (vectors), P (predicates)

**Immediates (6 types):**
- Unsigned, signed, hex, float
- Logical immediates (encoded)
- Shifted immediates

**Other (10+ types):**
- PC-relative labels
- Condition codes
- Shift/extend types
- Memory addressing modes (base, offset, pre/post-index)

### Instruction Matching Algorithm

```cpp
const InstructionEntry* findInstruction(uint32_t opcode) {
    // Instructions sorted by specificity (most fixed bits first)
    for (size_t i = 0; i < 4013; i++) {
        if ((opcode & table[i].mask) == table[i].pattern)
            return &table[i];
    }
    return nullptr;
}
```

**Optimization opportunity:** Binary search possible since table is sorted.

#### 2. Complete Operand Formatters (1 week)
The current formatter has placeholder logic for only 6 operand types. Need to implement all ~30 types.

**Required for each operand type:**
- Field extraction logic
- Value decoding/transformation
- Format string generation
- Special case handling

**Example - Register formatter:**
```cpp
case OP_REG_GPR_X:
    if (field_value == 31 && op.type == OP_REG_GPR_XSP)
        offset += snprintf(buffer + offset, size - offset, "sp");
    else if (field_value == 31 && op.type == OP_REG_GPR_XZR)
        offset += snprintf(buffer + offset, size - offset, "xzr");
    else
        offset += snprintf(buffer + offset, size - offset, "x%u", field_value);
    break;
```

**Priority order:**
1. GP registers (X, W, SP, ZR) - ~40% of instructions
2. Unsigned immediates - ~25%
3. PC-relative labels - ~10%
4. Memory addressing - ~10%
5. FP/SIMD registers - ~8%
6. Condition codes - ~5%
7. SVE registers - ~2%

#### 3. Logical Immediate Decoding (2-3 days)
ARM64 logical immediates use a compressed encoding that must be decoded.

**Required:**
- Implement `DecodeBitMasks()` algorithm from ARM ARM
- Handle N, immr, imms fields
- Replicate pattern to 32/64 bits

**Reference:** ARM Architecture Reference Manual, section C1.2.4

#### 4. Memory Operand Formatting (2-3 days)
Memory operands have complex syntax variations.

**Required:**
- Base register: `[Xn]`
- Immediate offset: `[Xn, #imm]`
- Register offset: `[Xn, Xm{, LSL #amount}]`
- Pre-indexed: `[Xn, #imm]!`
- Post-indexed: `[Xn], #imm`
- Extended register: `[Xn, Wm, SXTW #amount]`
